# Oric-1 / Atmos 问题与修复摘要

范围：`codex/oric1-atmos` 的 HW_CONFIG=16 Oric 适配，证据截至 2026-10-06。下表的“已验证”只指相应问题和所列场景，不代表整个 Oric 任务验收。

| 问题 | 定位证据与原因 | 处理和现状 |
|---|---|---|
| HIRES 测试图出现密集竖条 | 原测试 TAP 将 `0x40|(Y&63)` 填满 HIRES 显存，竖条是素材内容；还覆盖了文字叠加区。见 HVR-ORIC-004。 | 修正 `PicoES_Oric_Hires.tap` 的图案和文字区域。后续用户照片显示正常测试图；不能把旧图归咎于 HDMI 或 ULA。 |
| 启动时 HSTX 环分配失败、黑屏 | 候选 7 的 53,760 字节静态帧索引占 SRAM，链接后堆仅剩 4,192 字节，小于 HSTX 的 36,864 字节分配。见 HVR-ORIC-009。 | 改用 PSRAM 中 20,160 字节的 3-bit 帧，并在 HW16 构建检查 HSTX 前 SRAM 余量；后续候选已越过视频初始化。 |
| ROM 浏览器曾黑屏，但按 A 可进游戏 | 候选 13 `screen=0`、游戏帧为零，按 A 后画面和帧计数恢复；候选 16 的浏览器渲染成功且有非零像素，用户确认列表可见。见 HVR-ORIC-020/021。 | 通过分阶段启动日志将问题缩到浏览器显示阶段；故障未稳定复现，**精确根因未确认**，不记为已修复的公共视频缺陷。 |
| 个别候选停在 `PSRAM set_params` 后 | 候选 23 等未到 `PSRAM GUARD`；候选 24 的 Oric 本地 SRAM 启动保护后进入后续初始化。见 HVR-ORIC-029/030。 | 保留已能启动的本地启动保护。启动日志仅能确认停点和回归通过，不能据此断定所有板子的 QMI/RXDelay 根因。 |
| 第三方 TAP 提示缺少 `basic11b.rom` | SD 卡缺 Atmos BASIC ROM；用户提供的 Oricutron LHA 内有匹配的 16 KiB ROM。见 HVR-ORIC-033。 | 将用户提供的 ROM 放到 SD 的 `/roms/ORIC/basic11b.rom` 并核对哈希；ROM 未加入仓库或固件。换卡时需重新配置该资源。 |
| 两个 BASIC 小游戏加载后只显示 `Ready` | TAP 的 autorun 标志为 0，`CLOAD""` 后还需键入 `RUN`。见 HVR-ORIC-034。 | 识别为素材启动方式，不是模拟器卡住；手柄测试改用自动启动的 Cyclotron。 |
| Cyclotron 从加载到标题约一分钟 | 单块 4,069 字节机器码 TAP 走逐脉冲磁带，主机模拟约 45.5 秒客机时间；直接装载到同一标题约 7.8 秒。见 HVR-ORIC-037。 | 仅对单块、自动启动机器码 TAP 增加直载；其余 TAP 继续原磁带流程。候选 26 串口出现 `ORIC FASTLOAD bytes=4069 start=2540`，用户确认慢加载消失。见 HVR-ORIC-038。 |
| HIRES 测试音嘈杂，是否为音频故障不明 | 测试 TAP 原本写 AY 噪声寄存器；音频缓冲计数无法证明实际听感。见 HVR-ORIC-032/039。 | 增加独立 AY 声音测试 TAP；用户明确反馈“声音通过”。这只验收测试音场景，不推出所有游戏声音正确。 |
| 静态 HIRES 约 23 FPS | 测试图显存基本不变，仍反复重绘 224 行；ULA 约 4.9 ms/帧。见 HVR-ORIC-010/012。 | 跟踪 ULA 可见显存写入与闪烁相位，复用未变化画面；真机约 38.8–38.9 FPS，ULA 约 0.18–0.23 ms/帧。同版还有其他优化及升频，整体 FPS 增益不能全归因于此。 |
| Cyclotron 动态游戏内约 45–47 FPS，声音欠载增长 | 候选 29 分项采样显示 CPU、VIA 各约 5 ms，输入准备约 3 ms；候选 30 游戏内 `step=18.1–18.4 ms`，绘制约 2.6–2.9 ms，超过 PAL 约 19.96 ms 帧预算。见 HVR-ORIC-049/052。 | 候选 32 只在 VIA 定时器/IRQ、I/O 和磁带输入均稳定时跳过重复输入准备及通用 VIA 路径；边界走原逻辑。主机 140 帧和 Cyclotron 1,000 帧状态/画面/音频等价。用户游戏内日志 `fps=50.0–50.1`、`step=15.8–16.2 ms`、`over=0/101`、`audio_under=0`，并评价“完美”。见 HVR-ORIC-053。 |

## 回退和剩余风险

- 候选 28 的像素 LUT、候选 31 的 PSRAM 行暂存均使动态场景变慢，已回退；不能将其计入有效修复。
- 最新游戏内 `fps` 是客机逻辑帧率，部分同段 `display=45–49`，不等于每秒都展示 50 个不同画面。其它 TAP、长时间运行和完整 Oric 任务仍待独立真机验收。
- BIOS、游戏 TAP、声测 TAP 位于用户 SD 或忽略的构建目录；换卡应核对 `/roms/ORIC` 资源及 `/emu/16/oric.uf2`，避免把资源缺失误判为固件失败。

当前已测候选：`oric/_build/delivery/oric-viaquiet32/oric.uf2`；用户真机记录见 `.emv2/checkpoints/HVR-ORIC-053.md`。公共前端、Loader 和其它模拟器没有因以上修复改动。

## 每周期重复工作审查（2026-10-06）

以候选 29 的实测分项作定位基线，再审候选 32 的 `oric/core/oric.c::tick()`；旧分项不能当作候选 32 的当前耗时。

| 路径 | 已有避免重复工作的条件 | 仍需核实的开销 |
|---|---|---|
| VIA 与键盘/AY 输入准备 | 候选 32 在 VIA 延迟预算、无 I/O、磁带电平不变时复用外部引脚；边界仍逐周期处理。 | 已测 Cyclotron 获约 2–2.5 ms/帧收益；不宜再无条件跳过 VIA 计时、IRQ 或键盘变化。 |
| AY 寄存器读写 | 读取数据有 `ay_read_valid` 缓存；控制线或有效 VIA 写入变化时才调用 `ay38910_iorq`，避免每周期重启包络。 | 候选 29 的 `ay` 约 2.8 ms/帧，但含必要的音调、噪声、包络及采样推进；需要当前候选的独立分项和等价测试才能认定多余。 |
| AY 时钟 | 非 8 周期边界且无采样到期时直接推进计数器；边界调用通用 `ay38910_tick`。 | 进一步批量推进可能跨寄存器写入或采样边界；当前没有证明可安全省去的重复运算。 |
| 磁带 | `tape_tick` 每周期先检查未挂载、已读完和电机状态，满足任一条件立即返回；Cyclotron 直载后不会重复解析 TAP 块。 | 这仍是每周期一次轻量检查，但候选 32 已达到已测目标；需量出当前时间占比再考虑改变调度。 |
| 视频 | 只对脏行和闪烁相位变化重绘；无变化时适配器跳过取帧和绘制。 | 动态游戏本身会更新多行，约 2.7–2.9 ms 绘制不能仅凭调用次数判为冗余。`display=45–49` 需另查显示帧交付，不能用逻辑 FPS 代替。 |
| ROM/SD | 运行帧路径使用已载入内存的 BIOS/TAP 和 `memory[]`，未发现每帧重新扫描目录或读取 SD。 | 换卡导致的资源缺失属启动配置问题，不是每周期加载。 |

审查结论：已经证实的大量重复工作是 VIA 平稳周期输入准备，候选 32 已修复。AY、磁带和动态绘制仍有成本，但本次代码审查没有足够证据判定为“多余”，因此未修改固件。若后续游戏再次低于目标，先给候选 32 加采样分项并在同一游戏场景测量，再只改占比异常的路径。
